# 排班页日班次统计设计

## 目标

在排班管理页中，用户点击某个日期的单元格或表头后，页面顶部中间区域显示该日期各班次的人数。统计区域位于月份选择器与打印、导出按钮之间，使用紧凑标签展示，不显示日期或“班次统计”前缀。

## 方案选择

已确认采用内嵌统计条方案：统计条固定在工具栏中部，所选日期以表格列的浅蓝色高亮表示。

备选方案包括悬浮气泡（容易遮挡表格）和表格底部统计区（需要滚动才能看到）；两者均不采用。

## 界面与交互

- 点击日期表头或该日期任一排班单元格，更新当前选中日期。
- 统计条按班次显示为圆角标签，例如“活动 3”“器械 1”。
- 标签字号为 12px，间距紧凑；需要标红的班次沿用现有红色规则。
- 日统计标签按固定优先级显示：总务、责1、责2、8-3/夜、中、起休、休、器械、巡回；每个基础班次后紧跟同名加 `*` 的班次。未列入优先级的班次按中文名称升序排列。
- 不显示“7月9日·班次统计”等文字；用户通过当前高亮列识别统计对应日期。
- 没有选中有效日期或该日没有排班时，统计区域为空，不显示占位文案。
- 班次数量多于可用宽度时，统计条可横向滚动，不挤压打印和导出按钮。

## 数据与实现边界

- 不新增接口。前端基于当前已加载的 `tableData` 计算所选日期列的非空班次出现次数。
- 以单元格的完整班次值作为统计键；例如“8-3/夜”作为一个班次统计，不拆分文本。
- 保留 `POST /api/admin/scheduling/edit`，但请求体改为单个单元格：`userName`、`date`、`month`、`classes`；不再传递月份范围或整页 `schedulingInfos`。
- 后端按 `userName + date` 删除该单元格现有记录；`classes` 非空时插入该班次，空值时仅删除记录。操作在事务中完成，确保同一单元格不会留下重复记录。
- 前端下拉框允许清空。清空后提交空 `classes`，后端删除该日班次；请求失败时恢复编辑前的单元格值。
- 编辑保存成功后，若编辑日期是当前选中日期，重新计算顶部日统计；同时刷新底部统计表。
- 切换月份范围时清空当前选中日期与统计，防止显示旧数据。

## 验证

- 点击不同日期的单元格与表头，确认统计标签和列高亮同步切换。
- 验证空日期、多个班次、标红班次及班次数量较多的情况。
- 验证每次编辑请求只包含一个单元格，且后端只影响该人员该日期的记录。
- 验证清空班次会删除该日期记录；请求失败会恢复单元格旧值。
- 编辑当前日期排班后，确认统计数量立即反映最新值。
- 运行项目现有 lint 校验，并人工检查桌面宽度下工具栏、表格与按钮不重叠。
